# Exact-byte finite-verification gap, before repair

Recorded 2026-10-17 21:59 UTC. Nonauthor review of the exact theorem v7 / algorithm v1 / proof v8 triple in input-hashes.sha256. This is a finite specification gap, not a counterexample to the promised BDD recovery assertion.

Algorithm v1 Section 8 permits general certified computable scalar inputs, hence a computable, possibly nonrational d0. It computes rational interval upper endpoints U for residual moduli and then says to accept precisely when each U is at most 2d0. It calls this a fixed-precision rational upper-bound test and claims bounded bit budgets on all target inputs. But the threshold 2d0 is not specified to be rational, and no certified rational approximation or interval decision convention for that threshold is defined. Section 0's Up operation applies to integer precision/cutoff expressions; it does not supply this comparison.

For general computable-real input representations, exact comparison of a rational with a supplied real is not an available fixed-time operation. Arbitrarily accurate evaluation alone does not supply equality decisions. This is especially relevant to the explicit off-promise runtime claim, where there is no promised separation between a candidate's interval upper endpoint and 2d0. An implementation that refines until a strict sign is certified has no uniform stopping guarantee. An implementation that uses a fixed approximate threshold has to specify that threshold and its conservative rule; its literal behavior can differ from the current displayed predicate.

On the actual BDD promise this is easily repairable: the correct candidate has residual at most d0, while every incorrect lattice candidate has residual greater than 3d0. A rational threshold strictly between those ranges, with controlled relative precision and a certified residual upper endpoint, suffices. This observation does not silently replace the frozen algorithm's predicate. Likewise restricting all relevant scalars so d0 is an exact rational would be a statement change, not an interpretation inherited by the current theorem.

Disposition for the exact triple: full finite-algorithm acceptance is withheld at this narrow specification point. The Gaussian, comparison, causal-walk, reconstruction-margin and transcript-error calculations reviewed so far have not produced a mathematical counterexample. A changed algorithm/proof/theorem reference requires new hashes and a scoped exact-byte recheck, preserving this record.
